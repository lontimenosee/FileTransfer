# 项目总览

## 1. 这是什么项目

这是一个面向嵌入式系统课程期末设计的 Qt 项目。项目目标是实现一个基于 TCP 的网络文件传输工具，让 Windows 主机和嵌入式 Linux 开发板之间可以互传文件。

按照你现在的硬件条件，推荐的最终形态是：

- Windows 作为图形主机
- i.MX6U 作为无界面命令行节点
- 两边都具备发送和接收能力

当前代码还处于第一阶段，先完成：

- 服务端监听端口
- 客户端连接服务端
- 选择一个文件并发送
- 服务端接收后保存到指定目录

后续可以继续扩展：

- 大文件分块传输
- 目录传输
- 断点续传
- 传输校验
- 交叉编译部署到 i.MX6U

## 2. 为什么先做单文件传输

对于零基础同学，最容易卡住的不是写界面，而是“不知道先做什么”。如果一开始就同时做文件夹传输、断点续传、分块、校验，工程会非常复杂，也很难调试。

所以这个项目采用“先小后大”的路线：

1. 先把 TCP 通信打通
2. 再把单文件传输跑通
3. 再往上叠加更多高级功能

这样做有两个好处：

- 课程验收时，最基础的功能一定先能演示
- 后续加分项可以建立在已经可运行的工程上

## 3. 为什么用 TCP

本项目采用 `TCP`，原因很简单：

- TCP 自带可靠传输
- 按顺序到达，适合文件内容传输
- Qt 对 TCP 支持成熟，使用 `QTcpSocket` 和 `QTcpServer` 就能完成

如果使用 UDP，还要自己处理丢包、乱序、重传，这对课程设计来说不划算。

## 4. 为什么界面先做简单版

课程设计最重要的是：

- 功能正确
- 代码清晰
- 容易演示
- 容易写进报告

因此当前界面采用最直观的调试型布局：

- 输入 IP 和端口
- 选择文件
- 点击连接和发送
- 看日志和进度条

这样最适合调试网络程序。等基础版稳定后，如果你愿意，我们再继续美化界面。

## 5. 为什么现在要把 Windows 作为主控端

因为你的 `i.MX6U` 没有图形界面。

这意味着板端不适合承担“主要操作入口”的角色。更合理的方案是：

- Windows 负责操作界面
- Windows 负责调试
- Windows 负责自检
- i.MX6U 负责实际文件收发执行

这样既符合真实使用场景，也更适合课程答辩展示。
