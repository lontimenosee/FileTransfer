# 如何编译与运行

## 1. 在 Qt Creator 中打开项目

1. 打开 Qt Creator
2. 选择 `打开项目`
3. 打开根目录下的 `FileTransfer.pro`
4. 选择你的 `MinGW` Kit
5. 点击配置项目

## 2. 编译顺序

根工程是一个子目录工程，里面包含两个可执行程序：

- `FileTransferHost`
- `FileTransferClient`
- `FileTransferServer`

你可以在 Qt Creator 左侧工程树中看到它们。

当前更推荐优先编译和运行的是：

- `FileTransferHost`

## 3. 运行服务端

### 推荐方式：先运行统一主机版

1. 点击 `host_app` 工程
2. 运行 `FileTransferHost`
3. 在接收区域点击 `Start Listen`
4. 在发送区域连接 `127.0.0.1:8899`
5. 选择文件并发送

如果你只想做最简单的 Windows 自检，这就是首选方式。

## 4. 运行旧版服务端

先运行服务端程序：

1. 点击 `server` 工程
2. 运行 `FileTransferServer`
3. 保持默认端口 `8899`
4. 选择一个保存目录
5. 点击“开始监听”

## 5. 运行旧版客户端

再运行客户端程序：

1. 点击 `client` 工程
2. 运行 `FileTransferClient`
3. 输入服务端 IP
   - 如果在同一台电脑测试，填写 `127.0.0.1`
   - 如果跨设备测试，填写服务端实际 IP
4. 端口填 `8899`
5. 点击“连接服务端”
6. 点击“选择文件”
7. 点击“发送文件”

## 6. 运行结果

正常情况下：

- 客户端显示连接成功
- 客户端进度条逐渐到 100%
- 服务端日志显示收到连接
- 服务端进度条逐渐到 100%
- 服务端保存目录中出现接收到的文件

## 7. 常见问题

### 端口被占用

如果服务端无法监听端口，说明：

- 端口已被其他程序使用
- 或者上一次程序没有正常退出

可以换一个端口，例如 `9000`，并确保客户端端口也同步修改。

### 无法连接

请检查：

- 客户端 IP 是否正确
- 服务端是否已经开始监听
- Windows 防火墙是否阻止程序联网

### 板卡无法连接 PC

如果后面要连接 i.MX6U，请继续检查：

- 开发板和 PC 是否在同一网段
- 能否先互相 `ping` 通
- 板卡上是否能正常运行 Qt 程序

## 8. 目前更推荐的验证顺序

对于你的项目，不建议一开始就直接在板卡上调试。

更推荐这样做：

1. 先在 Windows 上做本机自检
2. 再做 Windows 与板卡的网络联通测试
3. 最后再把文件传输程序放到板卡上跑

这样做更省时间，也更容易定位问题。
