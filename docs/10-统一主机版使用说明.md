# 统一主机版使用说明

## 1. 为什么要新增统一主机版

前面的 `client/` 和 `server/` 工程适合分开调试协议，但你现在更需要的是：

- Windows 作为主机
- Windows 端可以发送文件
- Windows 端也可以接收文件
- Windows 端可以自己做自检

所以项目里新增了一个统一的 Windows 主机工程：

[host_app/host_app.pro](D:\Linux\QTcreater\Prj\FileTransfer\host_app\host_app.pro)

它生成的程序名是：

- `FileTransferHost`

## 2. 这个程序现在能做什么

统一主机版窗口里分成两个区域：

### Send Area

负责：

- 输入对端 IP
- 输入对端端口
- 选择要发送的文件
- 建立连接
- 发出文件

### Receive Area

负责：

- 设置监听端口
- 设置接收保存目录
- 开始监听
- 接收来自对端的文件

## 3. 这和以前的 client/server 有什么关系

可以这样理解：

- `client/` 和 `server/` 是第一阶段调试版
- `host_app/` 是更接近最终形态的 Windows 主机版

也就是说，后续课程设计展示时，更推荐你优先演示统一主机版。

## 4. 怎么在 Windows 上做“一个程序自检”

这是目前最适合你的验证方式。

步骤如下：

1. 运行 `FileTransferHost`
2. 在 `Receive Area` 中：
   - 监听端口填 `8899`
   - 选择接收目录
   - 点击 `Start Listen`
3. 在 `Send Area` 中：
   - 对端 IP 填 `127.0.0.1`
   - 对端端口填 `8899`
   - 点击 `Connect Peer`
   - 选择一个测试文件
   - 点击 `Send File`

这样就相当于：

- 同一个主机程序一边监听
- 一边连接自己
- 把文件发送给本机的接收逻辑

如果传输成功，就说明：

- 发送逻辑可用
- 接收逻辑可用
- 协议解析可用
- Windows 自检链路可用

需要注意的是，统一主机版现在的“发送成功”不再表示“本机已经把数据写进网络缓冲区”，而是表示：

- 接收端已经完成保存
- 接收端已经回发确认
- 发送端已经收到这条确认

这样更适合判断真实的大文件传输结果。

## 5. 自检成功后怎么进一步确认

自检成功后，建议你继续用哈希脚本比对文件：

[tools/compare_file_hash.ps1](D:\Linux\QTcreater\Prj\FileTransfer\tools\compare_file_hash.ps1)

这样就能证明：

- 文件不是“看起来收到了”
- 而是“内容完全一致”

## 6. 为什么这一步很重要

因为后面当你把板端接进来时，问题会变多：

- 网线是否正常
- IP 是否正确
- 板端 Qt 环境是否正常
- 板端权限是否正常

如果你不先做 Windows 自检，后面就很难分辨：

- 是代码逻辑有问题
- 还是板端环境有问题

所以统一主机版最大的价值，就是把“核心功能验证”和“平台适配问题”分开。

## 7. 本次主机版稳定性修复说明

为了提升跨设备传输的稳定性，主机版接收逻辑已经从“直接按 socket 即时读取”调整为“基于接收缓冲区的状态机解析”。

这样做的原因是：

- TCP 不是按“消息”到达，而是按字节流到达
- 文件头和文件内容可能被拆成多次到达
- 也可能多个部分一次性粘在一起到达

如果程序假设“一个 readyRead 就正好收到完整协议头”，就会在跨设备时出现：

- 小文件偶尔成功
- 稍大一点的文件不稳定
- 本机环回正常，但真实网络不稳定

现在统一主机版已经按更稳妥的方式处理这些情况，更适合继续做板端联调。
